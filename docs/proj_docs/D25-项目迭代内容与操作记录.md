## 1. 目标与范围

### 1.1 目标
1. 定义 `KnowledgeDocument`、`Chunk` 元数据及 RAG 模块边界。
2. 设计不少于 20 条起步评测问题，覆盖有答案、无答案、权限、故障码场景，固定问题与期望证据，形成可重复评测基线。

### 1.2 范围边界
本轮是**架构定义与评测基线设计**，不是完整 RAG 开发：
- 不接入向量数据库、Embedding、文档解析器或新增中间件；
- 不实现完整导入、切分、向量化、检索、重排、生成链路；
- 不编造设备知识、故障码、维修步骤、权限规则或知识来源；
- 不把示例字段写成项目已存在字段，不重建已有会话/模型/异常/日志能力。

## 3. 设计决策

1. **概念分离**：KnowledgeDocument 承载原始资料业务身份、来源、版本、权限与生命周期；Chunk 是检索单元，
   保留与父文档稳定关联、定位与检索元数据；不混淆文档/Chunk/Embedding/检索结果/回答。
2. **对齐现有字段**：documentId、title、sourceType、section、page、excerpt、url 沿用现有命名；
   企业治理与向量字段为新增“规划项”，代码暂无实现。
3. **权限责任**：权限字段是策略输入与过滤条件，真正裁决由独立鉴权能力在证据暴露前完成；
   Chunk 强制继承父文档权限、默认拒绝，切分不得扩大访问范围。
4. **版本失效**：文档内容变更生成新版本，旧 Chunk/向量/缓存按版本失效并可追溯；下线级联移除可检索集合。
5. **供应商隔离**：模型/向量库/Embedding SDK 仅存在于基础设施层，领域与业务接口只依赖端口抽象。
6. **故障码处理**：无显式码的用例设计为 abstain/clarify，禁止编造或跨设备套用代码含义。

## 9. 记忆简语

- **概念口诀**：`文档管身份，Chunk 管检索；Embedding 是向量，回答另生成，五者不混淆。`
- **权限口诀**：`先鉴权后给证据，子片段不超父权限；无鉴权先定契约，不把标签当裁决。`
- **验证口诀**：`可答必有真实出处，无据一律拒答澄清；格式校验加构建，端到端没跑不冒充。`
