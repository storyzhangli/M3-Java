## 1. 本轮做了什么（一句话）

给 D39 知识链路装上**服务端可信身份**与**检索前置权限过滤**：Bearer token → SHA-256 → MySQL 凭据表 → AuthContext；向量路与关键词路在 Top-K 之前按 租户/部门/设备 三键过滤（SQL WHERE 下推 + 倒排先过滤后排名），RRF 融合闭包，预览/raw/历史暴露面同步收口；**默认开关关闭，关闭时与基线逐字节零差异**。

## 7. 踩坑与工程教训（本轮真实记录）

1. **d39 骨架 PG 曾 0 行**：KP2 盘点发现骨架未自带入库——回归锚点类任务先验资产存在性，别把"空库"当"空结果"（熔断#2 先修资产再推进）。
2. **metadata 列是 json 不是 jsonb**：任务书编制假设 jsonb；SQL 层实证两种类型下缺失键谓词均 0 命中，fail-closed 语义等价——依赖版本敏感结论必须以本地实测为准。
3. **`Filter$Expression` 是 record**：字段 private，`getExpression()` 反射猜测失败；正确断言=访问器 `type()/left()/right()`+`Group.content()`，ExpressionType 常量大写。猜 AST 节点序也失败过——先 dump 真实 AST 再写断言。
4. **MySQL ALTER 无 IF NOT EXISTS**：information_schema 先查后改；首跑断言把 before=-1 哨兵误判成漂移（DDL 实际成功），修断言重跑幂等。
5. **GlobalExceptionHandler 吞 AccessDeniedException→5000**：专属 advice 必须 `@Order(-100)` 抢先精确接管，否则 4030 语义丢失。
6. **Result 恒 HTTP 200**：所有拒绝（4030/4001）都在 body.code；测试断言别盯 HTTP 状态（本轮 T8 首跑 `-Headers @()` 空数组绑定异常=同类坑）。
7. **delete 端点不联动 MySQL 主表行**（本轮实测新事实）：清理必须 PG/MySQL/倒排三处各自核验，"API 200"≠"清干净"。
8. **canonical 指纹行不含权限三键**：给 chunk 加 metadata 键不改指纹、增删行才改——这是 D5 夹具态/清理态两个指纹值能同时成立的根因，也意味着指纹**不能**单独证明"无越权"，必须配合打标行明细核验。
9. **PowerShell 字符串没有 .FullName**：`$baseline.FullName`（Join-Path 产物=string）静默为 null → 原生命令参数错位，报"未知参数"。路径变量要么一开始就 Get-Item，要么用 `.ToString()` 心智。
10. **工具输出污染对抗**：本轮多次遇到伪文件内容/伪 MISSING/假源码回显——一切判定锚定确定性证据（字节数、退出码、surefire 原文、javap、复算哈希）。
