## 一、概述

对同一冻结问题集（10 问）与同一冻结语料（3 文档），在真实 pgvector 链路上单变量比较检索参数（chunkSize / overlap / Top-K / threshold），量化 HitRate、Recall、Precision、噪声与三段耗时，输出参数影响结论与数据校准的推荐组合。

- 技术基线：JDK 21、Spring Boot 3.5.16、Spring AI 1.1.8、Maven 3.9.16、pgvector 0.8.7（PG 192.168.200.153/spring_ai）。
- 仓库基线：git `7fecbde`；Embedding：local-hashing-embedding/local-v1/384 维/COSINE；AI_MODE=mock（检索实验零 DeepSeek 调用）。

## 三、真实结果（270 条记录，0 请求错误，3 轮完全一致）

| 组 | HitRate | MacroRecall | Precision | 噪声 | 空检索 | 误检 | 平均耗时ms |
|---|---|---|---|---|---|---|---|
| G0 | 0.7778 | 0.7778 | 0.9286 | 0.0714 | 9 | 0 | 2.72 |
| G1 | 0.6667 | 0.6667 | 0.9167 | 0.0833 | 12 | 0 | 1.80 |
| G2 | 0.7778 | 0.7778 | 0.9286 | 0.0714 | 9 | 0 | 2.01 |
| G3 | 0.7778 | 0.7778 | 0.9286 | 0.0714 | 9 | 0 | 2.34 |
| G4 | 0.4444 | 0.4444 | 1.0000 | 0.0000 | 18 | 0 | 1.74 |
| B0 | 1.0 | 1.0 | 0.2383 | 0.7617 | 0 | 3 | 2.40 |
| B1 | 1.0 | 1.0 | 0.3333 | 0.6667 | 0 | 3 | 2.20 |
| B2 | 1.0 | 1.0 | 0.2783 | 0.7217 | 0 | 3 | 2.54 |
| B3 | 1.0 | 1.0 | 0.2383 | 0.7617 | 0 | 3 | 1.75 |

**结论**：阈值影响最大（0→0.25→0.35：Recall 1.0→0.7778→0.4444，Precision 0.2383→0.9286→1.0）；chunkSize 500 稀释细粒度信号伤召回（G1 新增 Q004 漏召回）；overlap 与 Top-K 在本语料无显著效应（库仅 5 chunk，K=10 超库存）；耗时 1.7–2.7ms、检索段主导，组间差异小于抖动。
**推荐**：200/20/5/th≈0.22–0.24（可回答 Top1 最低 0.2408，无答案 Q010 Top1=0.2144，窗口内同时保召回拒误检）。仅限本地哈希 Embedding + 冻结语料，不外推。

```powershell
# 0) 前置：MySQL/Redis 本机运行；PG 192.168.200.153 可达；PG_VECTOR_PASSWORD 已设置

# 2) 编译打包

# 3) Boot1（G0 切分 200/20，表 d36_exp_g0）
$env:PGVECTOR_DB_PASSWORD=$env:PG_VECTOR_PASSWORD   # 会话级桥接，不持久化
$env:CHUNK_SIZE="200"; $env:CHUNK_OVERLAP="20"; $env:PGVECTOR_TABLE="d36_exp_g0"; $env:AI_MODE="mock"

# G3: topK=10；G4: th=0.35；B0: th=0；B3: topK=10,th=0（同 Boot1）

# 5) Boot2/Boot3：停应用 → CleanupChunkRows（清本实验 chunk 关联行）→
```
