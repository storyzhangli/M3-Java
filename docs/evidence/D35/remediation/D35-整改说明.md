# D35 整改说明：引用归属校验与 Claim-Citation 关联验证

> 需求编号：D35-R02（整改切片）
> 基线提交：`d81f141`（D35 项目迭代）
> 范围：仅处理验收提出的两项 P1 缺陷；不改检索算法、不改 Embedding 维度、不改 D34 生命周期策略、不新增端点。

## 1. 缺陷一（P1-01）：Chunk 与 Document 归属未校验

### 1.1 现象

响应前核验只判断“documentId 存在”“chunkId 存在”，未判断该 Chunk 是否属于该 Document。构造 `documentId=DOC-A`、`chunkId=CHUNK-B`（实际归属 DOC-B）时，两份记录都存在，引用被判合法。最终返回给用户的是 DOC-B 的正文，却配上 DOC-A 的标题、版本、页码。

### 1.2 根因

`CitationVerificationService.loadChunks` 只收集 `Set<String>` 的 chunkId 存在性，丢弃了 `DocumentChunkIndexPO.documentId` 这一权威归属列；`classify` 的判定链缺少归属环节。证据侧 `EvidenceItem.documentId` 来自向量 metadata（`SimilarityMatchView.from` 读取 metadata.documentId），与 Chunk 行归属是两处独立数据，必须交叉校验。

### 1.3 修复

- `loadChunks` → `loadChunkOwners`：一次 `IN` 查询返回 `chunkId -> documentId` 映射；同一 chunkId 出现多个不同归属时映射为 `null`，表示归属歧义。
- `classify` 判定顺序：文档行缺失 → `CITATION_TARGET_DELETED`；chunkId 缺失或查不到 → `CITATION_TARGET_DELETED`；归属为 `null`/空白 → `CITATION_OWNERSHIP_MISMATCH`；归属与 `item.documentId` 不等 → `CITATION_OWNERSHIP_MISMATCH`；归属一致后才进入 D34 生命周期 `isEffective` 判定。
- `RagErrorCode` 追加 `CITATION_OWNERSHIP_MISMATCH`（共 21 个原因码）。
- `RagOrchestrator.selectRemovalCode` 优先级：`CITATION_TARGET_DELETED` > `CITATION_OWNERSHIP_MISMATCH` > `EVIDENCE_NOT_EFFECTIVE`。
- `reasonText` 补充新码的用户可读文案；类 Javadoc 补充归属校验说明。

### 1.4 保持不变的约束

- 仍是 document_id、chunk_id 两条批量 `IN` 查询，无 N+1。
- D34 的 DRAFT/DEPRECATED 拒绝、LOOKUP_FAILED fail-closed 未放宽。
- 不修改检索、向量写入、Embedding 维度与相似度阈值。

## 2. 缺陷二（P1-02）：Claim 未能逐条绑定自己的 Citation

### 2.1 现象

回答“S1=0.6、S2=0.8”时写成“工作压力 0.8 [S1]”。原实现把所有证据事实汇总为全局 `supportedFacts`，只要 0.8 在任意证据出现过就通过，错配引用被当作合法。

### 2.2 根因

`ResponseValidationService.checkFactualSupport` 以“全体证据事实并集”为判定域，断言与引用之间没有归属关系；引用合法性（`[S1]` 在白名单内）被误当成事实支持。

### 2.3 修复

- 证据侧构建 `Map<sourceRef, Set<subject|parameter|value>>`（`factsByRef`），每条证据只贡献自己那组事实；删除全局 `supportedFacts`。
- 回答侧确定性关联：
  1. 按 `。！？；` 与换行切句；
  2. 句内用 `MARKER_RUN_PATTERN = (?:\[S\d+\]\s*)+` 切块，文本块归属其后的标记组；
  3. 句末残余文本沿用最近标记组；整句无标记时，仅允许继承向前/向后相邻的“纯引用句”标记，遇到含正文句子立即停止；
  4. 每个 Claim 只有在归属标记组内至少一个合法引用支持时才通过；`[S1][S2]` 视为同一组，任一支持即通过；
  5. 无标记或错配 → 进入 `unsupportedClaims`，并写入新增 `claimCitationMismatches` 明细。
- `CitationValidationResult` 扩展为 6 组件（新增 `claimCitationMismatches`），保留 5 参与 4 参构造器；`CitationValidationView` 增加同名字段；`RagOrchestrator.toValidationView` 回填。

### 2.4 边界

该校验是确定性字符串与参数匹配，不宣称自然语言语义证明；无法确定时保守失败，不默认放行。复杂跨句指代、同义改写可能漏判，这是有意选择的安全侧偏差。
