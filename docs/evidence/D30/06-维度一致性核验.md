# D30 证据 06：维度一致性核验（384 基线落地，整改后）

> 取证方式：读取 `EmbeddingProperties` 源码、`application.yml` 配置，并以真实测试断言与真实写入验证。
> 整改说明见证据 12；基线出处见证据 02。

## 一、EmbeddingProperties 真实默认值

来源：`com.zl.d30.document.embedding.config.EmbeddingProperties`

| 字段 | 真实默认值 |
| --- | --- |
| provider | `local` |
| model | `local-hashing-embedding` |
| modelVersion | `local-v1` |
| dimensions | **384** |
| maxInputLength | 8192（UTF-16 字符，非 Token） |
| distanceMetric | `COSINE` |
| maxAttempts | 3 |
| initialBackoffMs | 200 |
| backoffMultiplier | 2.0 |
| maxBackoffMs | 5000 |

## 二、application.yml 显式 embedding 块（决策自文档化）

```yaml
app:
  ai:
    embedding:
      enabled: ${EMBEDDING_ENABLED:true}
      provider: ${EMBEDDING_PROVIDER:local}
      model: ${EMBEDDING_MODEL:local-hashing-embedding}
      model-version: ${EMBEDDING_MODEL_VERSION:local-v1}
      dimensions: ${EMBEDDING_DIMENSIONS:384}
      max-input-length: ${EMBEDDING_MAX_INPUT_LENGTH:8192}
      distance-metric: ${EMBEDDING_DISTANCE:COSINE}
```

显式写出 `dimensions: 384`，使维度基线在配置中可直接读取；所有字段均可由环境变量覆盖。

## 三、模型真实输出：float[384]

`LocalHashingEmbeddingModel` 以维度作为特征哈希桶数，构造期读取配置：

```java
this.dimensions = properties.getDimensions();
this.embeddingDimensions.set(dimensions);

float[] vector = new float[dimensions];                  // 真实 384 长度
int bucket = FeatureHasher.bucket(feature, dimensions);  // 0..383
```

单测断言（真实计算，非 Mock）：

| 测试 | 断言 |
| --- | --- |
| `LocalHashingEmbeddingModelTest.dimensionsMatchConfig` | `model.dimensions() == 384` |
| `outputHasExpectedDimensions` | `vector.length == 384` |
| `callReturnsOneEmbeddingPerInput` | 每条输出 `length == 384` |
| `emptyTextReturnsZeroVectorWithCorrectDimensions` | 空文本仍为 384 长度、模长 0 |

## 四、模型与表维度对齐（fail-closed）

`PgVectorStoreConfiguration` 同时读取配置与模型维度并断言：

```java
int dimensions = embeddingProperties.getDimensions();   // 384
int modelDimensions = embeddingModel.dimensions();      // 384
if (modelDimensions != dimensions) {
    throw new IllegalStateException("EmbeddingModel 维度与配置维度不一致……");
}
```

| 来源 | 真实值 |
| --- | --- |
| `EmbeddingModel.dimensions()` | 384 |
| `EmbeddingProperties.dimensions` | 384 |
| `vectorSpaceId` 末段 | 384 |
| 正式表 `vector(N)` | vector(384)（证据 07） |
| 集成测试断言 | `vector(384)` |

## 五、真实测试覆盖

- `PgVectorStoreConfigurationTest.vectorStoreBuiltWithMatchingDimensions`：384 对 384 正常装配，距离类型 `COSINE_DISTANCE`；
- `PgVectorStoreConfigurationTest.vectorStoreRejectsDimensionMismatch`：模型返回 256、配置 384 时**抛 IllegalStateException**，
  证明旧 256 模型无法与 384 基线混用；
- `VectorIndexCompatibilityServiceTest`：384 同模型 `COMPATIBLE`、512 `DIMENSION_MISMATCH`、384 异模型 `MODEL_SPACE_MISMATCH`；
- `EmbeddingControllerTest`：`dimensions=384`、`vectorSpaceId` 末段为 384。

## 六、真实写入反向验证

384 端到端写入 3 条成功（证据 08），若模型仍输出 256，`vector(384)` 列会直接拒绝写入并抛 DataAccessException；
写入成功即反证模型与表维度真实一致。

## 七、长度口径澄清

- 输入长度单位为 **UTF-16 code unit**（`String.length/substring`），**字符数 ≠ Token**；
- 本轮不引入 Tokenizer、不宣称 Token；Embedding 输出 `float[]`，默认 L2 归一化，距离默认 COSINE。

## 八、结论

维度 384 已在「属性默认值、显式配置、模型真实输出、vectorSpaceId、正式表 DDL、测试断言」六个层面一致落地，
并由启动期断言与单测双重保证 fail-closed；256 与 384 不可混写的约束有真实测试支撑。
