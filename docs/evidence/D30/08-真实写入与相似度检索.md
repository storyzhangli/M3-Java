# D30 证据 08：真实写入与相似度检索（端到端 HTTP）

> 取证方式：真实启动 Spring Boot 应用（端口 8080），经 HTTP 调用三个端点。
> 临时脚本：`http_demo.ps1`；应用启动日志：`logs/D30/08-app-run.log`；原始输出：`http_demo_out.md`。

## 一、写入前统计

```json
{
  "code": 200,
  "data": { "table": "\"public\".\"d30_vector_store\"", "count": 0 }
}
```

## 二、真实写入 3 条

请求文本（均带 `testRun` 标记，便于严格清理）：

```text
1. postgres pgvector 向量数据库 存储与索引
2. java spring boot 后端服务 开发与配置
3. redis 缓存 会话 设计与过期策略
```

响应：

```json
{ "code": 200, "msg": "success", "data": 3 }
```

`data=3` 表示 3 条文本经 EmbeddingModel 真实向量化后写入 pgvector。

## 三、真实余弦相似度检索（真实结果）

查询：`pgvector 向量 数据库 索引`，topK=3，threshold=0.0。

```text
排名  文本                                   score      distance
1    postgres pgvector 向量数据库 存储与索引   0.741684   0.258316
2    java spring boot 后端服务 开发与配置       0.199754   0.800247
3    redis 缓存 会话 设计与过期策略             0.162400   0.837600
```

### 关键核验点

1. **语义相关命中第一**：与查询共享「pgvector/向量/数据库/索引」的文档真实排名第一；
2. **降序正确**：score 严格降序，符合 `<=>` 余弦距离排序；
3. **score + distance ≈ 1**：第一名 `0.741684 + 0.258316 = 1.0`，
   印证 pgvector 余弦距离到相似度（`1 - distance`）的换算真实生效；
4. **分数区间合理**：所有 score 落在 [0,1]，非人为编造。

## 四、写入后统计

```json
{ "code": 200,
  "data": { "table": "\"public\".\"d30_vector_store\"", "count": 3 } }
```

count 由 0 真实增长到 3，与写入条数一致。

## 五、维度不匹配的真实拒绝（集成测试）

`PgVectorStoreIntegrationTest.wrongDimensionInsertIsRejected`：
向 vector(256) 列原始写入 3 维向量，**断言抛出 DataAccessException**，对应 pgvector
`expected 256 dimensions, not 3` 的 fail-closed 约束，错误维度无法落库。

## 六、取证后清理

- 执行 `http_cleanup.py`：`DELETE 3`，回读 `remaining = 0`；
- 停止应用，确认端口 8080 已释放；
- 演示数据按标记严格清理，未触碰任何用户数据。

## 七、结论

真实端到端链路（HTTP → 服务 → 本地 Embedding → pgvector 写入 → 余弦 `<=>` 排序 → 结果回读）已实际跑通，
排序、相似度换算、行数变化、维度拒绝均有真实数据支撑；这是「检索成功」的直接证据，而非仅「连接成功」。
