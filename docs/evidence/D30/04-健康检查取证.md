# D30 证据 04：健康检查取证

> 取证方式：容器 healthcheck 状态 + `pg_isready` + 容器日志，三路交叉验证。
> 原始记录见 `logs/D30/03-ssh-environment.md`。

## 一、Docker 原生健康检查

`docker ps` 中容器状态为：

```text
pgvector-pg18   pgvector/pgvector:pg18   Up 2 hours (healthy)
```

Compose 中健康检查定义：

```yaml
healthcheck:
  test: ["CMD-SHELL", "pg_isready -U postgres -d spring_ai"]
  interval: 5s
  timeout: 3s
  retries: 10
```

状态标记为 `(healthy)`，证明 Docker 健康检查在真实周期内持续通过。

## 二、pg_isready 真实输出

命令：`docker exec pgvector-pg18 pg_isready -U postgres -d spring_ai`

```text
/var/run/postgresql:5432 - accepting connections
退出码: 0
```

`accepting connections` 且退出码 0，数据库服务端真实可接收连接。

## 三、容器日志（启动与运行）

```text
2026-11-13 16:08:45.906 CST [1] LOG:  starting PostgreSQL 18.7 ...
2026-11-13 16:08:45.909 CST [1] LOG:  listening on IPv4 address "0.0.0.0", port 5432
2026-11-13 16:08:45.913 CST [1] LOG:  listening on Unix socket "/var/run/postgresql/.s.PGSQL.5432"
2026-11-13 16:08:45.924 CST [1] LOG:  database system is ready to accept connections
```

- 日志显示监听 `0.0.0.0:5432` 与 Unix socket，并明确 `ready to accept connections`；
- 后续为周期性 checkpoint 正常记录，无错误、无崩溃、无重启异常。

## 四、口径区分（重要）

| 结论 | 状态 |
| --- | --- |
| 数据库进程启动、可建立连接 | **已通过（真实）** |
| 向量检索功能正确 | 需另行验证（见证据 08），连接成功 ≠ 检索成功 |

## 五、结论

健康检查经 Docker 状态、`pg_isready`、数据库日志三路一致确认通过；
但本轮严格区分「连接成功」与「检索成功」，检索正确性以证据 08 的真实写入/查询结果为准。
