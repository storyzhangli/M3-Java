# D31 证据 02：稳定 ID 与幂等数据模型

> 取证方式：源码 + 真实 MySQL information_schema 回读；DDL 见 `D31_VSUAI/src/main/resources/db/schema-document-vector-index.sql`。

## 一、稳定 Chunk ID 设计

`StableChunkIdGenerator`（`com.zl.d31.document.vectorindex.support`）：

- 算法：RFC4122 **UUID v5（SHA-1）**；
- 固定命名空间 UUID：`0f9f7d52-6b3e-4a1c-9f2d-7c8e5b3a6d41`；
- 名称串：`documentId|version|strategy|chunkIndex|chunkContentHash|splitVersion`；
- 输出：version=5、variant=2 的标准 36 字符 UUID，满足 PG `UUID.fromString` 要求。

设计覆盖任务书硬约束：

| 约束 | 落点 |
| --- | --- |
| 考虑来源/标识/顺序/内容指纹/切分版本 | 名称串含 documentId、chunkIndex、chunkContentHash、splitVersion |
| 失败重试不生成新 ID | 输入不变 → UUID v5 确定性输出，重试同 ID |
| 不同文档内容相同也要区分 | 名称串含 documentId，跨文档 ID 不同 |
| 切分版本演进可区分 | 名称串含 splitVersion，改切分规则即换 ID |

## 二、文档级状态表 document_vector_index（14 列）

一个文档版本一行，兼作轻量 Outbox/任务表：

- 关键字段：document_id、version、content_hash、strategy、chunk_count、
  status（PENDING/INDEXING/COMPLETED/PARTIAL/FAILED/SUPERSEDED）、
  stage（SPLIT/EMBED_WRITE/SWITCH/CLEANUP）、error_code、error_message、
  attempt_count、next_retry_at、created_at、updated_at；
- 约束（真实 information_schema 回读，non_unique=0）：
  - `uk_doc_version(document_id, version)` UNIQUE；
  - KEY `idx_status_retry(status, next_retry_at)`、`idx_status_updated(status, updated_at)`。

## 三、Chunk 级关联表 document_chunk_index（14 列）

一个 chunk 一行：

- 关键字段：document_id、version、strategy、chunk_id(CHAR36 UUID)、chunk_index、
  **content(MEDIUMTEXT，Outbox 载荷快照)**、chunk_content_hash、char_length、
  global_start、global_end、status(INDEXED/FAILED)、时间戳；
- 约束（真实回读，non_unique=0）：
  - `uk_chunk_id(chunk_id)` UNIQUE；
  - `uk_doc_ver_strat_idx(document_id, version, strategy, chunk_index)` UNIQUE；
  - KEY `idx_document(document_id, version)`。
- `content` 列先建表后以 `ALTER TABLE ... ADD COLUMN content MEDIUMTEXT ... AFTER chunk_index` 补上，
  现 information_schema 回读为 14 列。

```text

document_chunk_index    uk_chunk_id             0           chunk_id
document_chunk_index    uk_doc_ver_strat_idx    0           document_id,version,strategy,chunk_index
document_chunk_index    idx_document            1           document_id,version
```

`NON_UNIQUE=0` 即数据库级真实唯一约束，满足任务书「不能只靠 Java 先查后插，必须 DB 唯一约束防并发」。

## 五、旧表冲突（待用户决策，未做破坏性操作）

实际 MySQL 的 `knowledge_document` / `knowledge_document_page` 是旧版 D25 schema，与当前代码不匹配：

- knowledge_document：实际 `source_system`（代码 PO 为 source）、`version varchar(64)`（代码 Integer）、
  file_name/content_type/file_size（代码 content_length），缺 content_length；
- page 表：实际 character_count（代码 content_length）、blank_page（代码 blank）、
  parser_name/parser_version，缺 source/title/version/created_at；
- 两表均 0 行；模块内 `CREATE TABLE IF NOT EXISTS` 不会改旧表。
