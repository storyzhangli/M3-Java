# D31 证据 03：主键回写缺陷定位与修复（关键根因）

> 取证方式：真实跑集成测试观察失败现象 → 结合 MyBatis 机制定位 → 修复后用真实测试结果验证。
> 失败日志：`logs/D31/it-run-04.txt`（修复前 4 失败）、`it-run-05.txt`（修复后 11 全绿）。

## 一、现象（修复前真实结果）

`DocumentVectorIndexIntegrationTest` 11 个测试中 4 个失败、0 错误：

| 测试 | 断言 | 实际 |
| --- | --- | --- |
| scenario2 重复导入 | `repeat.isIdempotent()` 期望 true | false |
| scenario3 更新切换 | 旧版本 PG 数期望 0 | 3 |
| scenario3b 新版本失败 | v1 状态期望 COMPLETED | INDEXING |
| uniqueConstraint | 期望 DuplicateKeyException | 未抛出 |

## 二、根因分析

前三个失败指向同一根因：**自定义 `@Insert` 未回写自增主键，导致所有 `updateById` 成为空操作**。

调用链：

1. `DocumentVectorIndexMapper.upsertOnNaturalKey` 是手写 `@Insert ... ON DUPLICATE KEY UPDATE`，
   默认不把 MySQL 自增 `id` 写回 PO；
2. 首次插入后 `task.getId()` 始终为 `null`；
3. 后续所有状态推进都调用 `indexMapper.updateById(task)`（含 `VectorIndexStateTx.switchVersion`
   与最终置 COMPLETED），MyBatis-Plus 生成 `UPDATE ... WHERE id = NULL`，匹配 0 行，静默不生效；
4. 因此数据库中任务行停留在插入时的 `INDEXING`：
   - 重复导入读回状态非 COMPLETED → 幂等短路不命中；
   - 版本切换 `updateById` 空转 → 旧版本未置 SUPERSEDED，清理查询找不到 SUPERSEDED 行，旧向量不删；
   - v1 行在库里从未真正变成 COMPLETED（并非被 v2 改写）。

## 三、修复（最小改动）

在 `DocumentVectorIndexMapper.upsertOnNaturalKey` 上加 `@Options` 回写主键：

```java
@Options(useGeneratedKeys = true, keyProperty = "id", keyColumn = "id")
@Insert(""" ... ON DUPLICATE KEY UPDATE ... """)
int upsertOnNaturalKey(DocumentVectorIndexPO po);
```

- 插入后 `task.id` 被真实填充，后续 `updateById` 正常生效；
- MySQL 在 ON DUPLICATE 命中已有行时同样回传该自增 id，重试/更新路径一致；
- 并发首建 catch 分支改用 `findIndexRow` 读出的胜出行，其 id 本就存在。

## 四、唯一约束测试的同步修正

`uniqueConstraint_rejectsDuplicateChunkId` 原用 `chunkMapper.upsertOnNaturalKey` 期望抛
DuplicateKeyException —— 但 Upsert 语义本就「冲突即更新」，不会抛错，属测试方法误用。

改为通过 MySQL 原生 `INSERT`（非 Upsert）验证 DB 约束：不同文档、相同 `chunk_id` 时，
MySQL 1062 被 Spring 翻译为 `DuplicateKeyException`，直接证明 `uk_chunk_id` 在数据库层生效。

## 五、验证（真实结果）

修复后注入环境变量重跑：

```text
Tests run: 11, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

测试断言经 `getStatus`/`listChunks` 真实回读数据库（非内存对象、非 Mock），
绿结果证明 DB 行确实到达 COMPLETED/SUPERSEDED，根因修复成立。

## 六、结论

这是一个「写入成功但状态机静默失效」的隐蔽缺陷：单看首次写入无法暴露，
正是任务书强调「验收看重复/失败/更新/删除后是否仍正确」的价值所在。修复仅一处注解 + 一处测试用法，
未改业务流程与表结构。
